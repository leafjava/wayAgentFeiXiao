# TokenTruth 项目说明与评委问答

## 30 秒介绍

TokenTruth 是一个面向代币投资者、RWA 发行方和合规团队的证据型项目研究平台。它把白皮书、代币规则、市场数据、解锁计划、风险提示和项目方公告整理成可追溯的知识库，让用户直接问：项目靠什么产生价值、代币代表什么权利、能否转让或赎回、当前最大的风险是什么。

系统回答会引用资料来源，并把重要披露、风险变化、投资者问答和用户授权记录生成哈希，必要时写入 Monad Testnet，形成可验证的证据链。

## 目标人群

- **普通投资者和研究者**：把分散的白皮书、规则和公告转换成易懂的权利与风险说明。
- **RWA 和代币发行方**：维护资料、生成版本差异、制作说明材料，并证明某份披露在什么时间已经发布。
- **合规券商、托管方和平台运营者**：查看 KYC、地区限制、赎回、分红、转让和底层资产字段。
- **审计、风控和评估人员**：根据来源、版本历史、市场快照和证据哈希复核结论。

## 它是不是专门防“老鼠仓”

准确说，TokenTruth 不是交易监控或执法系统，不能识别个人身份，也不能证明某个人实施了内幕交易。

它解决的是更前置的信息透明和证据留痕问题：

1. 记录团队、投资人和生态激励的解锁计划，提醒用户关注集中解锁和潜在抛压。
2. 保存资料版本变化，避免项目方事后修改规则却没有历史记录。
3. 把风险状态变化、重要公告和投资者问答做成可验证记录。
4. 在模拟购买前展示权利、限制和风险确认。
5. 对 RWA 区分底层资产、托管方、监管框架、赎回机制和地区资格。

准确表达是：**TokenTruth 是帮助用户发现信息不对称、识别解锁和治理风险、保留披露证据的研究与风控基础设施；它不能替代监管执法或链上反洗钱系统。**

## 产品主要功能

### 有来源的 AI 问答 `/chat`

用户可以询问商业模式、代币权利、转让规则、赎回、分红、托管、解锁和风险。回答关联知识库文档和来源链接；DeepSeek 不可用时，使用本地规则引擎返回确定性答案。

### 多维度项目分析 `/analyze`

从基本面、市场、社区/资料、风险四个维度整理项目；RWA 还增加底层资产、托管、监管、KYC、赎回、NAV 和审计字段。

### 项目和资料管理

`/projects` 展示项目目录，`/[projectId]` 展示资料详情，`/company` 和 `/edit` 支持资料更新、版本差异和项目方内容管理。

### 跟踪和模拟执行 `/track`

用户可以建立关注列表和投资计划，选择模拟平台、金额和风险偏好。购买、赎回、分红只生成模拟执行记录，不接触真实资金。

### 链上证据 `/proof`

重要操作会规范化、哈希化，并在 mock 或 Monad Testnet 模式下生成可验证记录。

## Demo 资产：PAX Gold（PAXG）

- 发行方：Paxos Trust Company, N.A.
- 底层资产：每枚 PAXG 对应一金衡盎司 London Good Delivery 黄金。
- 用途：获得黄金价格敞口，并在支持的区块链和市场转移代币化黄金权益。
- 是否代表 Paxos 股权：不代表。
- 是否有分红权：没有，PAXG 不是收益型股权代币。
- 是否可以赎回：可以通过 Paxos 按条款申请黄金赎回，受资格、费用、最低额度和地区限制约束。
- 是否可以转让：可在 Ethereum 和支持的二级市场转移，但交易平台和司法辖区可能有限制。
- 购买资格：直接铸造/赎回通常需要 Paxos 账户、KYC/AML 和受支持地区；交易所规则另行适用。
- 主要风险：黄金价格、Paxos/托管方、智能合约、流动性、溢价折价、监管和地区限制风险。

官方资料：[PAXG Overview](https://docs.paxos.com/guides/stablecoin/paxg)、[PAX Gold Whitepaper](https://www.paxos.com/wp-content/uploads/2019/09/PAX-Gold-Whitepaper.pdf)、[Paxos Terms](https://www.paxos.com/terms-and-conditions)、[Transparency Reports](https://www.paxos.com/attestations/)。

## 模拟购买流程

1. 选择 PAXG，查看权利、市场快照、资料来源和风险。
2. 选择国家/地区，完成模拟资格检查。
3. 连接 EVM 钱包；Demo 使用 mock 或 Monad Testnet，不使用真实资金。
4. 输入模拟金额，按静态价格计算数量。
5. 确认价格、托管、智能合约、流动性和监管风险。
6. 提交模拟订单，生成订单 ID、证据哈希和 PAXG 收据。
7. Monad Testnet 模式可生成测试网交易，但不代表真实资产所有权。

不能购买或需要人工审核：地区不支持、KYC 未完成、金额低于最低额度、钱包未连接、未完成风险确认，或 RWA 资产要求合规券商审核。

## 评委常见问答

### Q：和普通 AI 聊天机器人有什么区别？

A：普通聊天机器人可能给出没有来源的总结。TokenTruth 先整理项目资料、版本、市场快照和风险字段，再基于资料回答，并返回出处和可信等级；重要操作还能生成链上哈希。

### Q：如何防止 AI 胡说？

A：回答优先来自结构化规则和项目文档，每个回答带引用、来源和置信度。资料不足时明确说“未披露”，不凭空推测。DeepSeek 是增强层，不是唯一事实来源。

### Q：这是投资建议或交易平台吗？

A：不是。系统提供资料整理、权利解释、风险提示和模拟流程，不做收益承诺、不托管资金、不撮合真实订单，也不绕过 KYC。

### Q：是不是在防老鼠仓？

A：不做个人身份追踪或执法判断。我们记录解锁、公告、版本和授权证据，帮助用户发现信息不对称和潜在利益冲突，让项目方难以事后无痕修改披露。

### Q：为什么使用区块链存证？

A：数据库适合查询，链上哈希适合证明内容在某个时间点已经存在且之后未被悄悄替换。我们不上链敏感个人信息，只保存必要的哈希和元数据。

### Q：为什么选择 PAXG？

A：PAXG 的底层资产、发行方、托管、赎回和官方文档较清楚，且有公开二级市场数据，适合演示“代币到底代表什么”。

### Q：静态市场数据可靠吗？

A：第一版使用带时间戳的数据快照，不冒充实时行情。页面显示数据来源和更新时间；生产版本应接入行情 API，并保存每次抓取记录。

### Q：项目方可以修改资料吗？

A：可以提交新版本，但系统保留旧版本和差异。重要披露会生成内容哈希，方便比较之前和现在的说法。

### Q：如果项目方不披露托管方怎么办？

A：系统把“未披露”作为风险信号，不会自动猜测。缺少托管、监管、赎回或审计信息时，会提高风险提示等级。

### Q：Monad Testnet 的作用是什么？

A：用于演示低成本的链上证据写入和查询，只证明 Demo 操作流程，不代表真实资产发行，也不涉及真实资金。

### Q：项目的商业价值是什么？

A：投资者需要清楚的资料和风险解释，发行方需要可维护的披露和版本证明，平台与合规团队需要结构化资格、权利和限制字段。TokenTruth 把这些需求放进同一条可追溯工作流，降低研究、沟通和审查成本。

## 一句话收尾

**TokenTruth 不告诉用户“买什么”，而是帮助用户先弄清楚“自己买到的到底是什么、依据是什么、风险在哪里、之后能否验证”。**

## 链上查证是做什么的

链上查证不是用来证明项目一定安全，也不是用来替代法律或审计。它解决的是“这条记录有没有被事后改掉”和“别人能不能独立复核”两个问题。

TokenTruth 会对以下内容生成规范化哈希：

- 项目方披露文件和版本；
- 风险状态变化；
- 投资者问答和引用的资料版本；
- 用户购买前的风险确认和执行授权；
- 模拟订单和执行结果。

链上只保存哈希、类型、时间和必要的项目 ID，不保存姓名、身份证、API Key、完整问答或其他敏感信息。任何人拿到原文后，都可以重新计算哈希，确认它是否与链上记录一致。

## “跟踪执行”是怎么运作的

跟踪执行是一个投资研究和授权工作流，不是自动交易机器人：

1. 用户选择项目和平台，建立关注项。
2. 用户设置金额、风险偏好和跟踪频率。
3. 系统保存价格快照、公告、解锁、风险状态和资料版本。
4. 发生重要变化时，系统生成提醒或要求重新确认。
5. 如果用户主动发起购买、赎回或分红操作，系统先检查资产类型、平台能力、地区和资格字段。
6. 用户明确确认金额、风险和授权范围后，才生成模拟执行记录或 Monad Testnet 交易。
7. 系统返回订单 ID、执行状态、证据哈希和来源。

跟踪的是“事实和授权状态”，不是替用户预测价格，也不会在后台自动下单。

## “帮买币”是怎么运作的

Demo 中的“帮买币”分为两种模式：

### Mock 模式

默认使用 Mock 模式。用户输入模拟金额，系统根据静态价格计算数量，生成模拟订单和收据，不连接交易所、不使用真实资金、不产生真实所有权。

### Monad Testnet 模式

演示时可以连接 EVM 钱包并使用测试网代币。系统只发送测试网交易，用来演示授权、签名、证据哈希和状态查询。测试网交易不代表真实资产购买。

### 真实交易边界

TokenTruth 当前不托管资金、不代持资产、不收集私钥、不要求用户把资产转入平台，也不绕过交易所或券商的 KYC。生产环境若接入真实交易，只能通过具备资质的交易所、券商或托管方 API，并且必须由用户在自己的账户和钱包中完成最终确认。

## 如何确保合规和安全

### 合规控制

- RWA 项目单独记录底层资产、托管方、监管框架、赎回、分红、KYC 和地区限制。
- 不把普通加密资产的转账逻辑直接套到股票、债券或基金代币上。
- 用户未完成资格检查、风险确认或人工审核时，不生成可执行订单。
- 不向用户承诺收益，不把 AI 回答包装成投资建议。
- 真实交易必须交给持牌平台，TokenTruth 只负责资料、风险和授权记录。

### 安全控制

- 不保存用户私钥和助记词。
- API Key 只放服务器环境变量，绝不写入前端或链上。
- 链上只写哈希和非敏感元数据。
- 所有执行都需要用户主动授权，不能静默执行。
- 记录订单状态、授权时间、风险确认和错误信息，方便审计。
- 外部资料保留来源链接、发布时间和可信等级，避免把未知来源当成官方信息。

### 评委可以这样问，开发者这样回答

**问：你们会不会偷偷帮用户下单？**

答：不会。默认是 Mock 模式；测试网模式也必须由用户连接钱包并签名。系统没有用户私钥，无法代表用户转移资产。

**问：你们是不是在绕过 KYC？**

答：不会。Demo 只模拟流程；RWA 真实购买必须经过发行方、券商或托管方的 KYC、AML、地区和投资者资格检查。

**问：链上哈希能证明资产是真的吗？**

答：不能单独证明。哈希只能证明某份资料或记录没有被悄悄替换。资产储备、托管和法律权利仍要结合发行方披露、审计和适用法律判断。

**问：如果价格突然变化，系统会自动卖出吗？**

答：不会。系统可以提醒价格或风险变化，但不会在后台自动交易。任何执行都需要用户主动发起和确认。
